# 세 시선으로 본 프로젝트 점검

2026-11-04 작성. 저장소를 읽기만 했고 코드는 바꾸지 않았으며 커밋도 하지 않았다. 질문은 "이 프로젝트 이대로 괜찮다고 생각해? 새로운 시선, 채용자 입장, 학생 입장에서 생각해봐"였다.

근거는 `README.md`, `docs/` 전부, `web/src`의 홈·설정·품질·개인정보 화면, `feed`와 `notice` 패키지의 AI 관련 소스, 테스트 23개 파일, CI 설정, git 기록 65건이다. 실제 배포 주소와 CI 실행 결과는 네트워크를 쓰지 않아 보지 못했다(5절).

표의 "관찰"은 저장소에서 본 사실이고, "판단"은 내 의견이다.

## 결론

- **만듦새는 괜찮고, 서비스는 아직 아니다.** 테스트 142개, 정답셋 백테스트, 보지 않은 공지로 잰 AI 수치, 솔직한 한계 절은 주니어 포트폴리오에서 드물다. 그런데 ADR 007이 "목적은 학생이 실제로 쓰는 서비스를 운영해 보는 것"이라 적었는데 배포 전이고(`README.md:13`), 사용자는 0명이며, 운영 일지는 비어 있다(`docs/ops-log.md:19`). 첫 커밋(10-26)부터 9일 동안 ADR 13편을 쓰는 사이 학생은 한 명도 들어오지 않았다.
- **지렛대 1. 배포하고 학생 10명을 받는다.** `robots.txt` 결정(ADR 010 "남은 결정")을 내리면 막는 것이 없다. 운영 숫자 한 줄이 측정 문서 열 쪽보다 세 시선 모두에게 더 큰 증거다.
- **지렛대 2. 서로 어긋난 말을 맞춘다.** README가 "Haiku는 받아 적는 일만 한다"(`README.md:53`)고 하면서 같은 문서가 대상 조건 읽기를 핵심 결정으로 꼽고(`README.md:27`), ADR 013은 한 문서 안에서 AI 읽기를 "끈다", "켰다", "꺼짐이다"로 세 번 다르게 적는다. 설정 화면은 "홈 위쪽으로 올라와요"라고 약속하는데 홈은 플래너라 올라가는 것이 없다.
- **지렛대 3. 정답지에 사람 손을 넣고, 그림에서 읽은 날짜임을 학생에게 알린다.** 형광펜 정답지는 사람 확인 0건이고(`src/main/resources/quality/audience.json:4`), 그림 날짜는 사람 없이 공개되면서 화면에 표시를 안 하기로 했다(ADR 010). 채용자는 앞을, 학생은 뒤를 먼저 본다.
- 확신도. 저장소 사실은 높다. 채용자와 학생의 반응은 추정이고, 실제 학생 조사나 채용 담당자 의견은 없다.

주니어 백엔드 또는 풀스택 서류를 거르는 시니어가 30분 본다고 가정했다.

| `.run/` 안에 `campus-alimi.key` 등 SSH 개인키가 있다. `.gitignore`에 들어 있고 추적되지 않는다 | 저장소 문제는 아니지만 프로젝트 폴더 밖으로 옮기는 편이 안전하다 |

### 면접을 보고 싶을까

보고 싶다. 근거는 통합 테스트, 정답셋 CI, 떼어 둔 시험 셋, 기능을 끈 기록, 솔직한 한계다. 주니어 서류 중 상위에 든다고 본다. 다만 "운영한 서비스"라는 말은 지금 쓸 수 없고, 면접에서 가장 먼저 "왜 사용자가 0명인가", "정답지를 사람이 안 본 수치를 왜 공개했나", "robots.txt는 어떻게 할 건가"를 받게 된다. 이 셋에 답이 준비돼 있으면 강점이 되고, 없으면 측정이 목적이 된 프로젝트로 읽힌다.

## 3. 학생 입장

성심교정 재학생이 에브리타임 대신 이것을 쓸지를 생각했다. 실제 학생에게 묻지는 않았다.

### 진짜 아픈 곳을 긁나

| 관찰 | 판단 |
|---|---|
| 장학 31건 중 13건이 시·군·구 연고 조건이고(ADR 008 9행), 23%는 날짜가 그림에만 있다(ADR 010 3행). 공식 앱은 2021년 이후 갱신이 없고 게시판에 RSS가 없다(`docs/verification/2026-10-29-personalization.md:38`) | 마감을 뽑아 주는 것은 실제 빈자리다. "남의 지역 장학을 접는다"도 학생이 바로 알아듣는 가치다 |
| 장학과 학사를 더해 월 32~42건, 하루 1건 남짓이다(`personalization.md:37`) | 매일 열 이유는 없다. 주간 플래너(ADR 012)와 아침 메일 한 통은 이 빈도에 맞는 선택이다. "매일 돌아올까"에는 아니오, "주에 한 번과 메일"에는 예다 |
| 학과 게시판 36곳은 범위 밖이고, 표본 두 학과에서 8개월 동안 학과 장학 4건과 졸업시험 신청 마감이 중앙 게시판에 없었다(`personalization.md:41`). 성의·성신교정도 밖이다(`application.yml:53`) | 학생이 가장 자주 놓치는 것은 학과 공지다. 여기 없으면 "결국 학과 단톡은 따로 봐야 하네"가 된다. 첫 사용자 10명의 학과로 정하겠다는 계획(ADR 002 9행)은 맞지만 그 10명이 아직 없다 |

### 날짜를 믿을까

| 관찰 | 판단 |
|---|---|
| 품질 페이지(`web/src/app/quality/page.tsx:57-72`)가 정밀도 97.7%를 공개하고 "정답은 사람이 아니라 더 큰 모델이 적었어요"까지 적는다(246행) | 공개 자체는 신뢰를 준다. 다만 학생은 97.7%를 "40개 중 1개는 틀린다"로 바꿔 읽지 않는다. "원문 링크를 꼭 확인하세요"가 행마다 보이는 편이 숫자보다 낫다 |
| 그림에서 읽은 날짜는 화면에 표시하지 않기로 했다(ADR 010 15행, `docs/design.md:68`) | 반대로 가는 편이 학생에게 유리하다. "그림에서 읽음" 작은 표시 하나면 학생이 그 행만 원문을 열어 본다. 숨기면 틀렸을 때 서비스 전체가 의심받는다 |
| 마감 시각은 "9시", "18시" 같은 표기를 아직 읽지 않는다(`docs/verification/2026-10-29-image-ocr.md:47`) | 장학 마감은 18:00이 흔하다. 날짜만 맞고 시각이 비면 당일 저녁에 놓친다. 학생이 느끼는 "틀림"에 들어간다 |
| 신고는 로그인해야 하고 행의 "자세히" 안에 접혀 있다(`page.tsx:339-347`) | 신고 하나로 날짜가 내려가니 로그인 요구는 맞다. 다만 위치가 깊어 실제로 눌릴지 의문이다 |

### 온보딩이 무겁나

| 관찰 | 판단 |
|---|---|
| 로그인 없이 홈과 혜택을 다 본다. 로그인은 이메일 링크 하나(`settings/page.tsx:155-174`), 비밀번호 없음, 세션 30일 | 가볍다. 좋다 |
| 프로필 다섯 칸 전부 선택(`settings/page.tsx:185-291`). 이번 학기 선택은 입학년도를 넣어야 열린다(207행). 전공은 자유 입력이고(225행) 끝말을 뗀 글자 포함으로 맞춘다(`AudienceFacts.sameDept`) | "컴공", "컴정공"처럼 줄여 쓰면 형광펜이 안 칠해지고 학생은 이유를 모른다. 학과 목록에서 고르게 하면 없어지는 문제다 |
| 프로필을 다 넣어도 "내 것"이라 말할 수 있는 공지는 24%다(ADR 008 17행). 설정 화면은 "홈 위쪽으로 올라와요"라고 약속한다(182행) | 다섯 칸의 대가가 작다는 것을 서비스가 이미 안다. 그런데 화면은 큰 약속을 한다. 기대와 결과의 차이가 이탈을 만든다 |

### "내게 맞음"이 이해되나

| 관찰 | 판단 |
|---|---|
| 형광펜은 "내게 맞음"과 "저장"에 같이 칠해진다(`page.tsx:318` `task.mine \|\| task.saved`, `design.md:38`). 글자 표시 "내게 맞음"은 메타 줄의 작은 `<i>`다(337행). 이유는 "자세히"를 열어야 보인다(339-341행) | 노랑이 두 뜻이라 처음엔 헷갈린다. 이유 문장("3학년·컴퓨터정보공학부 대상, 자격 조건은 원문 확인")은 잘 썼으니 접지 말고 바로 보이면 된다 |
| 프로필이 비면 형광펜은 한 번도 안 칠해진다(`AudienceFacts.reasonFor` 107행, 118행). 그런데 화면에는 "왜 안 칠해지는지"가 없다 | 프로필 없는 학생에게 "설정에서 학기와 지역을 넣으면 여기 노랗게 표시돼요" 한 줄이 필요하다 |

### 학생이 기대할 텐데 없는 것

| 없는 것 | 근거 | 판단 |
|---|---|---|
| 푸시 알림 | ADR 004에서 첫 출시에서 뺐다 | 메일을 매일 여는 학생은 적다. 메일 열람률을 재 보기 전에는 확신할 수 없지만, 이 빈틈이 "돌아오지 않는" 첫 이유일 가능성이 크다 |
| 캘린더 내보내기(ics, 구글 캘린더) | 저장소에 없다 | 저장한 마감을 내 캘린더에 넣는 것이 학생이 가장 먼저 바랄 기능이다. 서버 없이도 만들 수 있다 |
| 끝냈어요가 기기 사이에 안 맞음 | `page.tsx:445-461`, `design.md:72` localStorage만 | 휴대폰에서 체크한 것이 PC에 없다. 로그인했으면 서버에 둬도 비용이 없다 |
| 학과 공지, 다른 교정 | 위 표 | 가장 큰 빈자리 |
| 오늘 마감 당일 알림 | ADR 004는 저장한 마감 3일 전 한 번 | 3일 전 메일을 보고 잊으면 끝이다 |
| 다크 모드, 네이티브 앱 | `design.md:42` 없음, PWA 매니페스트만(`layout.tsx:9-11`) | 지금 단계에서는 없어도 된다 |

### 매일 돌아올까

아니다. 공지 빈도와 설계가 모두 주 단위다. 돌아오게 하는 것은 메일인데, 메일은 로그인과 저장을 전제로 하고 지역·특정 대상·취업 공지는 넣지 않는다(ADR 004). 그래서 실제 재방문 경로는 "주초에 한 번 열고, 저장한 마감의 3일 전 메일"이다. 이 경로가 작동하는지는 사용자가 생겨야 안다.

## 5. 확인하지 못한 것

- 실제 배포 주소와 서버 상태. README가 배포 전이라 적었고 네트워크를 쓰지 않았다.
- GitHub Actions가 실제로 통과했는지. 워크플로 파일만 읽었고 실행 기록은 보지 않았다. 태그가 없으므로 이미지 빌드 단계가 돌았는지도 모른다.
- `./gradlew test`와 `npm test`를 이번에 돌리지 않았다. 테스트 수는 `@Test` 주석을 센 값이고 마지막 통과 기록은 검증 문서의 숫자(75개 통과 등)뿐이다.
- 실제 학생의 반응. 3절은 저장소의 자체 조사와 내 추정이다.
- 채용 담당자의 반응. 2절은 시니어가 서류를 보는 상황을 가정한 것이다.
- 정답지 라벨의 실제 정확도. 사람 확인이 10건과 0건이라 저장소도 모른다.
- Claude API 호출 코드(`ClaudeImageTranscriber`, `ClaudeAudienceClassifier`)의 동작. 테스트는 인터페이스 가짜로만 돌고 이번에 API를 부르지 않았다.
