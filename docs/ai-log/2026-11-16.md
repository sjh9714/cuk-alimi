# 2026-11-16

인계 노트. 2026-11-14 평가와 재설계 결정, 11-16 구현과 푸시를 적는다.

## 결정 (2026-11-14, 사용자)

- 서비스를 다른 공지 앱과 일정 도구에 나란히 놓고 평가했다. 아이디어는 낫지만 화면이 믿음직하지 않다는 결론이었다. 근거와 비교는 ADR 015에 있다.
- 범위는 "핵심만 남기고 재설계". 서버의 수집, 추출, 정답셋은 그대로 둔다.
- 덜어낸 것은 월 보기, 설정의 웹 푸시, 공개 품질 페이지다. 혜택 탭은 남겼다.
- 시각 방향은 시안 A "조용한 도구". 시안 셋과 재설계 전 화면은 `docs/research/2026-11-14-home-directions/`에 있다.
- 관심 주제 밖의 일은 기본으로 접는다.

## 바뀐 것 (커밋 2ed74e4부터 e93a7a4까지, main에 푸시)

- `docs/design.md`를 다시 쓰고 ADR 015를 더했다. ADR 004, 009, 011, 012, 014 맨 위에 현재 상태를 적었다.
- 홈은 한 열 목록이다(`web/src/app/page.tsx`). 이번 주, 다음 주, 이달 안, 그 뒤로 묶고 접힌 줄은 관심 밖, 다른 대상, 날짜 확인 중 셋이다.
- 관심 밖 나누기는 웹이 행 단위로 한다(`splitByInterest`, `web/src/lib/tasks.ts`). 서버의 `Feed.build`와 정답셋 고정 파일은 바꾸지 않았다.
- 아침 메일의 새 공지도 같은 규칙으로 거른다(`DigestService.inInterest`).
- 색 토큰을 흰 바탕과 먹색으로 바꾸고 종류별 색, 점 종이, 상자를 없앴다. 설정과 홈의 설명 문장을 줄였다.
- README와 화면 사진을 바꿨다. 사진은 정답셋 공지를 로그인 전 상태로 띄운 화면이다.

## 확인한 것

- `./gradlew test` 173건 통과(건너뜀 3건). 웹은 타입 검사, 테스트 42건, 빌드 통과. GitHub CI는 6b03d90과 e93a7a4에서 통과했다.
- 행 제목 공개 점수는 그대로다. 개발 88/96, 새 공지 7/17.
- 정답셋 카드로 답하는 임시 서버로 390px와 1280px에서 홈, 혜택, 설정을 봤다. 요약 줄의 링크가 접힌 줄을 여는 것, 저장하면 목록으로 올라오는 것, 체크하면 건수가 주는 것을 브라우저에서 확인했다.
- 로컬 DB로 띄운 실제 홈은 건수만 확인했다. 로그인 전 기준 이번 주 2건, 다음 주 2건, 관심 밖 15건(학점교류 8, 비교과 4, 취업 3)이었다. 2026-11-06 이후 공지의 행 제목은 새 공지셋을 위해 읽지 않았다.
- `RUN_ONCE=reparse`로 최근 90일 공지 136건을 지금 규칙으로 다시 뽑았다(원문 없는 1건 건너뜀). 그 전에 DB를 덤프해 두었다.

## 확인하지 못한 것

- 실제 DB에 로그인한 브라우저에서 저장과 체크를 눌러 보지 않았다. 임시 서버에서만 눌러 봤다.
- 검수 화면과 개인정보 화면은 눈으로 보지 않았다.
- 아이폰 실제 기기에서 보지 않았다.

## 다음에 할 일

1. **형광펜의 뜻을 다시 정한다.** 로컬 DB에서 세어 보니 시험 계정 둘 다 목록의 행 전부에 형광펜이 칠해졌다(11행 중 11행, 14행 중 14행). 관심 주제로 먼저 거르기 때문이다. 지금은 목록 안에서 아무것도 구분하지 못한다.
2. 새 공지셋. 2026-11-06 이후 공지는 11-16 기준 12건이다. 25건이 쌓이면 보지 않은 채로 새 셋을 뽑는다. 로컬 수집은 Docker가 꺼져 11-13 뒤로 멈춰 있었고 11-16에 다시 켰다.
3. 행 이름을 만드는 곳이 넷이다(웹, 캘린더, 푸시, 점검). 캘린더 일정의 이름이 화면과 다르다.
4. 취업·채용을 고른 학생은 홈에서 취업 공지를 보지만 새 공지 메일은 받지 못한다.
5. 배포는 보류 그대로다.
