# 2026-11-16

인계 노트. 2026-11-14 평가와 재설계 결정, 11-16 구현과 푸시를 적는다.

## 결정 (2026-11-14, 사용자)

- 서비스를 다른 공지 앱과 일정 도구에 나란히 놓고 평가했다. 아이디어는 낫지만 화면이 믿음직하지 않다는 결론이었다. 근거와 비교는 ADR 015에 있다.
- 범위는 "핵심만 남기고 재설계". 서버의 수집, 추출, 정답셋은 그대로 둔다.
- 덜어낸 것은 월 보기, 설정의 웹 푸시, 공개 품질 페이지다. 혜택 탭은 남겼다.
- 시각 방향은 시안 A "조용한 도구". 시안 셋과 재설계 전 화면은 `docs/research/2026-11-14-home-directions/`에 있다.
- 관심 주제 밖의 일은 기본으로 접는다.

## 바뀐 것 (커밋 2ed74e4부터 e93a7a4까지, main에 푸시)

- `docs/design.md`를 다시 쓰고 ADR 015를 더했다. ADR 004, 009, 011, 012, 014 맨 위에 현재 상태를 적었다.
- 홈은 한 열 목록이다(`web/src/app/page.tsx`). 이번 주, 다음 주, 이달 안, 그 뒤로 묶고 접힌 줄은 관심 밖, 다른 대상, 날짜 확인 중 셋이다.
- 관심 밖 나누기는 웹이 행 단위로 한다(`splitByInterest`, `web/src/lib/tasks.ts`). 서버의 `Feed.build`와 정답셋 고정 파일은 바꾸지 않았다.
- 아침 메일의 새 공지도 같은 규칙으로 거른다(`DigestService.inInterest`).
- 색 토큰을 흰 바탕과 먹색으로 바꾸고 종류별 색, 점 종이, 상자를 없앴다. 설정과 홈의 설명 문장을 줄였다.
- README와 화면 사진을 바꿨다. 사진은 정답셋 공지를 로그인 전 상태로 띄운 화면이다.

## 확인한 것

- `./gradlew test` 173건 통과(건너뜀 3건). 웹은 타입 검사, 테스트 42건, 빌드 통과. GitHub CI는 6b03d90과 e93a7a4에서 통과했다.
- 행 제목 공개 점수는 그대로다. 개발 88/96, 새 공지 7/17.
- 정답셋 카드로 답하는 임시 서버로 390px와 1280px에서 홈, 혜택, 설정을 봤다. 요약 줄의 링크가 접힌 줄을 여는 것, 저장하면 목록으로 올라오는 것, 체크하면 건수가 주는 것을 브라우저에서 확인했다.
- 로컬 DB로 띄운 실제 홈은 건수만 확인했다. 로그인 전 기준 이번 주 2건, 다음 주 2건, 관심 밖 15건(학점교류 8, 비교과 4, 취업 3)이었다. 2026-11-06 이후 공지의 행 제목은 새 공지셋을 위해 읽지 않았다.
- `RUN_ONCE=reparse`로 최근 90일 공지 136건을 지금 규칙으로 다시 뽑았다(원문 없는 1건 건너뜀). 그 전에 DB를 덤프해 두었다.

## 확인하지 못한 것

- 검수 화면과 개인정보 화면은 눈으로 보지 않았다.
- 아이폰 실제 기기에서 보지 않았다.

4. 취업·채용을 고른 학생은 홈에서 취업 공지를 보지만 새 공지 메일은 받지 못한다.

# 2026-11-16 (2). 근거 형광펜, 자격 접기, AI 문장 찾기

인계 노트. 같은 날 이어서 한 일이다. 결정의 근거는 ADR 016에 있다.

## 결정 (사용자)

- 대표 기능은 "근거 형광펜과 AI 문장 찾기"다. 형광펜을 "내게 맞음"에서 "날짜를 읽은 자리"로 옮긴다.
- 자격은 목록에 글자를 달지 않는다. 학년·학과가 안 맞는 일만 접고 조건 문장은 근거 패널에 보인다.
- AI 지출 상한은 월 20달러다. 앱의 가드와 Anthropic 콘솔 한도 두 곳에 건다.
- 모델은 첫 읽기 `claude-haiku-5-5`, 두 읽기가 엇갈릴 때만 `claude-opus-5-5`다.
- 기존 백엔드 포트폴리오(concert-booking 등)는 손대지 않는다. 앞으로의 포트폴리오는 이 서비스의 운영이다.

## 바뀐 것

- 날짜 항목에 근거 문장과 날짜 글자를 저장한다(V21). 행의 날짜를 누르면 근거가 펼쳐지고 날짜에 형광펜이 그어진다. 목록의 노란 칠은 없앴다.
- 자격을 맞음, 조건 없음, 확인, 안 맞음으로 가른다(`AudienceFacts.judge`, `Feed.eligibility`). 홈은 안 맞음만 "다른 대상"의 "학년·학과가 다름"으로 접는다. 접힌 행도 근거를 볼 수 있고 저장하면 돌아온다.
- AI 스위치를 셋으로 나눴다(`TRANSCRIBE_ENABLED`, `AUDIENCE_READ_ENABLED`, `LOCATOR_ENABLED`). 월 예산 가드(`AiBudget`)가 닿으면 AI 작업이 모두 멈춘다.
- 문장 찾기. 순수 부분(`NoticeText`, `QuoteCheck`, `LocatorMerge`), Claude 클라이언트(`ClaudeDeadlineLocator`), 운영 작업(`LocatorReader`, V22, 상태 `AUTO_AI`와 `HELD_AI`), 평가 도구(`LocatorLabelRun`, `LocatorBacktestTest`). 측정 뒤에 켰다.
- 보류한 날짜가 `/api/items?includePast=true`로 새던 것을 막았다.

## 확인한 것

- `./gradlew test` 전체 통과. 웹은 타입 검사, 테스트 48건, 빌드 통과.
- 행 제목 공개 점수와 마감 추출 수치는 그대로다. `gold-cards.json`은 근거를 실을 때 한 번 다시 만들었고 그 뒤로 바뀌지 않았다.
- 정답셋 카드로 답하는 임시 서버로 390px와 1280px에서 봤다. 날짜를 누르면 근거와 조건 문장이 펼쳐지는 것, 안 맞는 행이 "다른 대상"으로 가는 것, 접힌 행을 저장하면 목록으로 돌아오는 것을 브라우저에서 확인했다. 자격 값은 임시 서버가 흉내 낸 것이다.
- 가짜 문장 찾기로 병합표를 통합 테스트에서 확인했다. 규칙이 놓친 마감을 공개하고, 규칙의 날짜에 의심을 달고, 신고하면 둘 다 내려가 다시 올라오지 않고, 두 읽기가 엇갈리면 큰 모델이 정하고, 큰 모델이 없으면 보류한다.
- 규칙의 근거 문장을 인용으로 넣은 가짜 녹음으로 채점 배관을 돌려 봤다. 지시문 해시가 다르면 실패하는 것도 봤다. 이때 표의 칸 안 문단이 행을 쪼개던 문제를 찾아 고쳤다.

## 측정 (같은 날 오후, API 키를 받은 뒤)

- 녹음에 0.32달러를 썼다. 상한 5달러 가운데서다. 수치와 읽을 때의 단서는 ADR 016 "측정"에 있다.
- 개발셋(51건, 마감 54개). 규칙만 1.000 / 1.000이고 규칙과 AI도 1.000 / 1.000이다. AI만으로는 0.946 / 0.981이다.
- 개발셋 2(26건, 마감 20개, 한 번 잼). 규칙만 0.700 / 0.700에서 규칙과 AI 0.769 / 1.000이 됐다. 더한 6개가 모두 정답이고 보류한 3개는 모두 정답에 없다. 의심한 4개는 모두 규칙의 오류였다.
- **설계를 하나 바꿨다.** 작은 모델 두 표로 공개하려던 것을 "화면이 바뀔 때만 큰 모델이 확인"으로 바꿨다. 두 읽기가 틀릴 때 같이 틀려서다. 개발셋 2를 재기 전에 정했다.
- 재면서 고친 것. 평가 셋에서 운영이 읽지 않는 취업 공지 20건을 뺐다. 시각이 낀 기간("8월 12일 오후 1시 ~ 8월 18일")을 마감 둘로 세던 것을 하나로 이었다. 큰 모델의 하루 상한에 닿으면 보류로 굳히지 않고 다음 날 다시 확인받게 했다.
- 지시문은 두 번 다듬고 얼렸다(해시 `9b7e10163c14`). 특강 참석 날짜와 "예시" 날짜를 옮기지 말라는 줄은 작은 모델이 따르지 않았고, 그 둘은 큰 모델이 막는다.
- 문장 찾기 기본값을 켰다(`LOCATOR_ENABLED` 기본 true). 거부권은 켜지 않았다.

## 확인하지 못한 것

- **대표 수치가 아니다.** 개발셋 2는 문장 찾기를 설계할 때 본 셋이다. 새 공지셋에서 한 번 재기 전에는 "처음 보는 공지에서 재현율 1.000"이라고 말할 수 없다.
- 실제 모델로 운영 작업(`LocatorReader`)을 돌려 DB에 들어간 결과를 화면에서 보지는 않았다. 녹음과 재생은 같은 병합 코드를 쓰지만 저장과 화면은 가짜 모델의 통합 테스트로만 확인했다.
- 실제 DB에 로그인한 브라우저에서 자격 접기를 보지 않았다. 2026-11-06 뒤의 공지를 읽지 않으려고 임시 서버에서만 봤다.
- 검수 화면에서 AI 보류 날짜가 어떻게 보이는지 보지 않았다.

## 다음에 할 일

1. 새 공지셋에서 대표 수치를 낸다. 규칙과 지시문은 얼린 그대로 두고, 2026-11-06 뒤의 공지가 25건 쌓이면 보지 않은 채로 묶어 정답을 붙이고 한 번 잰다. 거부권도 그 수치로 정한다. 11-16 기준 12건이다.
2. Anthropic 콘솔에 월 한도 20달러를 건다(사용자).
3. 파서가 "2. 7일이내"를 2월 7일로 읽는 것은 그대로다. AI가 그 줄에 아무 말도 하지 않으면 의심도 달리지 않는다.
4. 학교 robots.txt 문의 메일(사용자). 이제 `TRANSCRIBE_ENABLED=false`로 그림만 끄고 배포할 수 있다.
5. 배포는 보류 그대로다.

## 세션을 닫으며 (2026-11-16 저녁)

- 사용자 결정. 배포 여부는 본인이 직접 써 보고 만족한 뒤에 정한다. 그 전에는 사용자 모으기도 하지 않는다.
- 로컬 상태. 백엔드(8080)는 AI 키와 `TRANSCRIBE_ENABLED=false`로 떠 있다. 대상 읽기와 문장 찾기가 돌고 그림 받아 적기는 꺼져 있다. 문장 찾기는 매시 45분에 하루 60건까지 읽는다. 웹 개발 서버(3000)는 `NEXT_PUBLIC_API_BASE=http://localhost:8080`으로 떠 있다. 둘 다 이 세션이 띄운 것이라 터미널을 닫으면 내려갈 수 있다.
- 로컬 DB는 2026-11-16에 다시 뽑아 날짜 항목에 근거를 채웠다(피드 52줄 중 45줄). 그 전 덤프는 세션 임시 폴더에 있어 오래 남지 않는다.
- 물어 두고 답을 받지 못한 것. 혼자 쓰는 비공개 서버에 올려 폰에서 써 볼지(아침 메일, 캘린더 구독, 폰 화면은 로컬에서 확인할 수 없다), 써 보는 기간을 2주로 둘지, 불만을 `docs/ops-log.md`에 모아 볼지, 새 공지의 날짜가 틀려도 새 공지셋을 재기 전에는 규칙을 고치지 않을지, robots 문의 메일을 이번 주에 보낼지, 첫 글을 쓸지, 지원 시점.
- 사용자가 할 일. Anthropic 콘솔에 월 한도 20달러 걸기. 클립보드에 남은 API 키 덮어쓰기.
