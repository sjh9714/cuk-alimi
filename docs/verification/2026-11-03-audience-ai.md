# 2026-11-03 형광펜 대상 조건 AI 읽기 측정

## 무엇을 쟀나

형광펜(내게 맞음)을 정규식 대신 AI가 읽은 대상 조건으로 칠하면 더 정확한지 쟀다(ADR 013). 공지는 `fixtures/notices-2026-10-26.json`의 62건이고, 결과 발표 1건은 홈에 나오지 않아 뺐다.

학생 프로필은 학년 1~4, 정답에 나온 학과와 해당 없는 학과(국어국문학과), 정답과 정규식에 나온 연고 지역과 지역 없음을 모두 조합한 336가지다. 공지마다 프로필마다 칠해야 하는지를 정답과 비교했다(`AudienceBacktestTest`).

## 정답지

API를 쓰지 않았다. 이 세션의 Claude Opus 5.5가 운영 지시문(`ClaudeAudienceClassifier.PROMPT`) 기준으로 62건의 제목과 본문을 직접 읽고 적었다(`fixtures/gold/audience.json`). 학년·학과·지역 조건이 있는 공지는 24건이다. 사람 확인은 아직 하지 않았다.

## 운영 모델 측정

API 키 파일이 /tmp 정리로 사라져 운영 호출 대신 Claude Code의 Haiku 서브에이전트 네 개로 쟀다. 두 개가 공지 31건씩 첫 번째 읽기를, 다른 두 개가 같은 공지를 두 번째로 읽었다. 운영 호출은 공지 한 건씩 구조화 출력으로 받으니 이 수치는 근사치다(`fixtures/gold/audience-haiku.json`).

### 1차

| 방법 | 정밀도 | 재현율 | 모두 맞은 공지 |
|---|---|---|---|
| AI | 86.9% | 34.4% | 49/61 |
| 정규식 | 77.3% | 45.3% | 51/61 |

AI가 학년과 지역은 대부분 맞게 읽었지만 두 가지에서 놓쳤다.
- "징계 없는 학생", "편입생은 따로" 같은 단서까지 그 밖의 조건이나 특정 계층으로 넣었고, 그 조건이 칠하기를 막았다.
- 한 번은 "경상북도 영주시"로, 한 번은 "영주시"로 적어 두 읽기가 어긋났다.

### 고친 것

- 비교 규칙. 특정 계층·과목만 칠하기를 막고, 소득·성적·그 밖의 조건은 칠하되 "자격 조건은 원문 확인"을 붙인다. ADR 008의 "맞을 수도 있는 것을 먼저 보여 주고 판단은 본인이" 원칙과 같다.
- 지역 이름. 줄여 적은 시·도와 시·도 없는 시·군·구를 목록으로 맞춘다(`Regions.parseLoose`).
- 지시문. 대부분의 학생이 해당하는 단서는 넣지 말라고 적고, 특정 계층을 "그 계층만 지원할 수 있는 공지"로 좁혔다.
- 같은 읽기의 기준. 칠하는 결정과 이유 문구가 같으면 같은 읽기로 본다.

1차 기록을 새 비교 규칙으로만 다시 채점하면 AI 95.6% / 68.9%, 정규식 95.0% / 41.0%였다.

### 2차 (새 지시문으로 다시 읽음)

| 방법 | 정밀도 | 재현율 | 모두 맞은 공지 | 잘못 칠한 쌍 | 놓친 쌍 |
|---|---|---|---|---|---|
| AI | 100.0% | 73.6% | 57/61 | 0 | 476 |
| 정규식 | 95.0% | 41.0% | 52/61 | 39 | 1064 |

두 읽기가 같았던 공지는 40/61건이다. 어긋난 21건은 정규식으로 돌아갔다. AI가 놓친 공지는 4건이다.
- 274824 학위수여식. 정답은 4학년이지만 두 읽기 모두 학년을 적지 않았다.
- 276474 의생명과학분야 장학. 한 번은 학과를 적고 한 번은 적지 않아 어긋났다.
- 276772 두산연강 장학. "2학년 1학기 진학 예정자"를 한 번은 1학년, 한 번은 2학년으로 읽었다.
- 276941 인송장학. 한 번은 학년을 적고 한 번은 적지 않았다.

### 3차 (실제 API, 같은 날 사용자가 새 키를 줌)

세션 근사치는 운영 호출과 조건이 달라 `AUDIENCE_RUN=haiku`로 운영 코드(`ClaudeAudienceClassifier`, 구조화 출력, 공지당 두 번)를 그대로 불렀다. 입력 토큰은 한 번 읽을 때 약 13만(형식 지시 포함 약 21만)이다.

| 회차 | 지시문 | 같았던 읽기 | 정밀도 | 재현율 | 잘못 칠한 쌍 | 비용 |
|---|---|---|---|---|---|---|
| API 1 | 2차와 같음 | 50/61 | 93.4% | 65.9% | 84 | $0.047 |
| API 2 | "2학년 진학 예정자는 지금 1학년", "지역 연고는 GROUP이 아님"을 더함 | 58/61 | 89.2% | 77.0% | 168 | $0.048 |
| 정규식 | | | 95.0% | 41.0% | 39 | 0 |

- API 1의 잘못 칠한 84쌍은 모두 276772(두산연강)였다. "2학년 1학기 진학 예정자"를 2학년으로 읽었다.
- API 2에서 그 공지는 맞았지만 276984(숙명여대 학점교류)의 "4학기 이상 이수, 졸업예정자 불가"를 2~4학년으로 읽어 168쌍을 잘못 칠했다. 정답은 3학년이다.
- 세션 근사치(2차)는 정밀도 100%였지만 실제 API에서는 재현되지 않았다. 근사 측정을 믿고 켜지 않은 것이 맞았다.

### 4차 (학기를 더한 뒤, 실제 API 한 번)

프로필에 이번 학기를 더하고 AI가 학기 조건을 `semesters`로 옮기게 했다. 정답지의 학기 조건 6건(276772, 276791, 276928, 276941, 276984, 277031)을 학기로 옮겼고, 학생은 학기 1~9 × 학과 × 지역 756가지다. 비용 약 $0.055.

| 방법 | 정밀도 | 재현율 | 모두 맞은 공지 | 같았던 읽기 |
|---|---|---|---|---|
| AI | 66.0% | 61.7% | 49/61 | 51/61 |
| 정규식 | 95.3% | 41.4% | 51/61 | |

- 275947, 276345(직무인턴)의 "정규학기(8차 학기 내) 재학"을 두 읽기 모두 [1~7]학기로 읽었다. 거의 모든 학생이 해당하는 조건이라 빈 목록이어야 한다. 두 공지에서 1,176쌍을 잘못 칠했다.
- 276791, 277031(학점교류)의 "1학년 이상 수료, 마지막 학기 불가"를 학년 [2,3,4]로 남기거나 아예 빼서 지시문의 "학기로 바꿔라"를 따르지 않았다.
- 276928(학생설계전공)의 "2학기 이상 재학생"을 학기 조건으로 읽지 않았다.

이 결과를 보고 지시문을 다시 고치지 않았다.

### 5차 (AI는 옮기고 계산은 코드가, 개발용 62건)

AI가 학기 문장을 종류와 숫자로만 옮기게 하고(`AudienceReading`), 학기 계산은 코드로 옮겼다.

| 회차 | 바꾼 것 | 정밀도 | 재현율 | 같았던 읽기 |
|---|---|---|---|---|
| 5-1 | 종류·숫자로 옮기기 | 82.6% | 86.9% | 46/61 |
| 5-2 | 정규 학기 7개 이상 해당은 조건 없음, 지시문에 "자격 문장만", "이수와 재학을 섞지 말 것" | 94.4% | 82.8% | 51/61 |
| 정규식 | | 95.3% | 41.4% | |

5-1에서 잘못 칠한 것은 국가근로 공지의 "2027년 2월 졸업예정자는 1월까지만 근로 가능"을 마지막 학기 제외로 읽어 1~7학기 거의 모두에게 칠한 것(588쌍)과 "2학기 이상 재학생"을 이수로 읽은 것이었다.

### 시험용 70건 (한 번만)

개발용과 겹치지 않는 장학·학사 공지 70건을 학교 게시판 31~150번째 글에서 1.5초 간격으로 받았다(`fixtures/notices-holdout-2026-11-03.json`). Opus 서브에이전트 둘이 기준 문서로 35건씩 정답을 적었고, 세션이 조건이 붙은 26건을 훑어 두 프로그램을 묶은 273402 하나만 고쳤다(`gold/audience-holdout.json`). 결과 발표 1건을 빼고 69건, 학생 2,700가지다.

| 방법 | 정밀도 | 재현율 | 모두 맞은 공지 | 잘못 칠한 쌍 | 같았던 읽기 |
|---|---|---|---|---|---|
| AI | 91.4% | 57.4% | 55/69 | 870 | 56/69 |
| 정규식 | 71.9% | 24.1% | 51/69 | 1,530 | |

오늘 실제 API에 쓴 돈은 측정 6번에 입력 319만 토큰, 출력 6.2만 토큰으로 약 $0.35다.

## 판단

계획의 켜는 조건(잘못 칠한 수가 정규식보다 늘지 않을 것)을 실제 API 측정에서 넘지 못해 `AUDIENCE_READ_ENABLED` 기본값을 껐다. 같은 공지로 지시문을 더 고치면 이 62건에만 맞추게 되어 멈췄다. 학기를 더한 4차에서도 나빠져 껐다가, 계산을 코드로 옮긴 5차 방식이 시험용 셋에서 정규식보다 잘못 칠한 것은 적고(870쌍 대 1,530쌍) 찾은 것은 많아(57.4% 대 24.1%) 다시 켰다. 기준선은 시험용 결과(정밀도 0.914, 재현율 0.574)다.

## 한계

- 정답과 측정 모두 API가 아닌 세션에서 만들었다. 정답은 사람이 확인하지 않았다.
- 1차 결과를 보고 같은 62건으로 지시문과 규칙을 고쳤다. 떼어 둔 공지로 잰 수치가 아니라 실제보다 좋게 나왔을 수 있다.
- 다음 할 일. 새로 들어온 공지로 따로 떼어 둔 셋을 만들어 다시 잰다. 프로필에 학기 정보가 없어 학기 조건은 학년으로 어림한다.

## 화면 확인

로컬 API를 새 코드로 다시 띄워 V12 마이그레이션을 적용했다. 시험 계정(3학년, 컴퓨터정보공학부)과 공지 한 건(277031 가톨릭계 학점교류)에 AI 조건 `[2,3,4]`학년을 넣고 1280, 390 폭에서 봤다. 형광펜이 칠해지고 자세히 안에 "내게 맞는 이유 · 2~4학년 대상"이 보였다. 정규식은 "1학년 이상 수료"를 읽지 못해 이 공지를 칠하지 않는다. 품질 페이지의 형광펜 정확도 표도 두 폭에서 가로 넘침 없이 나왔다. 시험 계정과 공지 값은 지웠다.
